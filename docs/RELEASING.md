# Releasing phora

Two workflows ship a release:

- `.github/workflows/release-plz.yml` prepares the release PR, publishes the crate, pushes the `v*` tag and starts the build.
- `.github/workflows/release.yml` is generated by cargo-dist from `dist-workspace.toml`. It builds the binaries, creates the GitHub Release and pushes the Homebrew formula.

## Triggers

| Workflow | Job | Runs on | Does |
| --- | --- | --- | --- |
| `release-plz.yml` | `release-pr` | push to `main`, Mondays 06:00 UTC, manual dispatch | Opens or updates the release PR. The PR bumps `version` in `Cargo.toml` and `Cargo.lock` and adds the new `CHANGELOG.md` section, rendered with git-cliff from `cliff.toml`. |
| `release-plz.yml` | `release` | same triggers | Publishes to crates.io when the `Cargo.toml` version is not published yet, pushes `v<version>`, then runs `gh workflow run release.yml --ref "$TAG" -f tag="$TAG"`. Does nothing when the version is already published. |
| `release.yml` | all | `workflow_dispatch` with a `tag` input | `plan`, `build-local-artifacts`, `build-global-artifacts`, `host`, `publish-homebrew-formula`, `announce`. |
| `release.yml` | `plan` | every pull request | Runs `dist plan` only (`pr-run-mode = "plan"`). Nothing is built or published. |

`release-plz.toml` sets `git_release_enable = false`: release-plz creates the tag and cargo-dist creates the GitHub Release.

For `0.x` versions, release-plz bumps the patch version for features and fixes, and the minor version for breaking changes. To take a larger step, see [Forcing a minor or major bump](#forcing-a-minor-or-major-bump).

## Secrets

| Secret | Scope | Used by |
| --- | --- | --- |
| `CARGO_REGISTRY_TOKEN` | crates.io token with publish scope | `release-pr`, `release` |
| `HOMEBREW_TAP_TOKEN` | `contents:write` on `srnnkls/homebrew-phora` | `publish-homebrew-formula` |
| `GITHUB_TOKEN` | provided by Actions | every job |

The `release` job grants its `GITHUB_TOKEN` `actions: write`, which is enough to dispatch `release.yml`. No personal access token is needed.

## Build matrix

`build-local-artifacts` builds six targets and attaches SLSA attestations:

- `x86_64-unknown-linux-gnu`, `aarch64-unknown-linux-gnu`
- `x86_64-unknown-linux-musl`, `aarch64-unknown-linux-musl`
- `x86_64-apple-darwin`, `aarch64-apple-darwin`

The aarch64 Linux targets run on `ubuntu-22.04-arm`. Installers: shell and Homebrew (`srnnkls/homebrew-phora`).

## Dry run

Run from the repository root:

```bash
mise exec -- release-plz release --dry-run
mise exec -- dist plan
mise exec -- dist generate --check
mise exec -- actionlint .github/workflows/*.yml
```

- `release-plz release --dry-run` shows what would be published.
- `dist plan` prints the artifacts cargo-dist would build.
- `dist generate --check` fails when `release.yml` differs from what `dist-workspace.toml` generates. Edit `dist-workspace.toml` and run `dist generate`; do not edit `release.yml` by hand.
- `actionlint` lints the workflows.

## Normal release

1. Merge work into `main`. `release-pr` opens or updates the release PR.
2. Review the version and the new `CHANGELOG.md` section in the PR. Edit the PR branch if an entry needs rewording.
3. Merge the release PR. `release` publishes the crate, pushes `v<version>` and dispatches `release.yml`.
4. Watch the `Release` run finish: binaries, GitHub Release, Homebrew formula.

## Forcing a minor or major bump

release-plz never picks a version above what the commits call for. Set the version by hand in a PR:

1. Branch from `main` and set `version` in `Cargo.toml`.
2. Refresh the lockfile:

   ```bash
   cargo update -p phora --offline
   ```

3. Add the release section to `CHANGELOG.md`. Print it with:

   ```bash
   mise exec -- git-cliff --unreleased --tag v<x.y.z>
   ```

   Paste the section above the previous release and match the existing heading and link format.
4. Commit as `chore(release): prepare <x.y.z>` and open a PR.
5. Merge. `release` sees an unpublished version and publishes, tags and dispatches as in a normal release.

Leave `release-plz.toml` unchanged. A setting such as `features_always_increment_minor` applies to every later release.

## Recovery

### Crate published and tag pushed, build never started

The dispatch step failed or was skipped. Dispatch the build with the tag:

```bash
gh workflow run release.yml --ref v<x.y.z> -f tag=v<x.y.z>
```

Do not re-run the `release` job. The version is already on crates.io, so the job skips it, reports no created release, and never reaches the dispatch step.

### Build started, a later job failed

- `publish-homebrew-formula` failed: re-run the failed job. Check that `HOMEBREW_TAP_TOKEN` is valid and `srnnkls/homebrew-phora` exists.
- A build job or `host` failed: re-run the failed jobs in the same run. No new dispatch is needed.

### Crate publish failed

No tag was pushed. Fix the cause (token, name ownership, version conflict) and re-run the `release` job.
